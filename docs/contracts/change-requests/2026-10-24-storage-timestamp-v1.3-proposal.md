## 1. 已批准且不重新申请的事项

新生成时间戳继续是 YYYY-MM-DDTHH:MM:SS.ffffffZ（UTC、包含秒、恰好六位微秒）。负责人已在本轮异步回复中确认含秒格式，当前代码无需调整。

必须保护既有秒、毫秒、微秒 Z 历史数据，保留微秒；+00:00 及已验证的更长小数正确性不得退化。原始 created_at/updated_at 不改写，公共字段仍为 str。

## 2. 现有问题与为什么需要批准

v1.2 仅约定 ISO-8601 UTC，未列举一个封闭的读取格式集合或合法但未支持表示的错误行为。现有 CTE 将基本式、逗号小数、零偏移其他写法、周/序数日期等生成 NULL 键并置尾，可能让 list_recent(limit=1) 返回较旧记录。报告问题并不消除运行时错排。

本建议明确读取 profile，并将无法比较的记录从“置尾返回”改为“显式失败”；还建议新增公共异常。这些是可见语义变化，必须取得负责人批准后才可实现，不能当作私有优化直接推进。

## 3. 推荐的 v1.3 读取 profile（全部待批准）

| 范围 | 推荐行为 |
|---|---|
| 扩展式完整公历日期 + 完整时分秒，Z 或 +00:00 | 必须兼容旧秒、毫秒、微秒；小数按真实值精确排序 |
| 基本式完整日期/时间 | 兼容 YYYYMMDDTHHMMSS[小数] 及 profile 明确列举的组合，不经 SQLite 日期函数判断 ISO 全集 |
| 小数分隔符 . 与 , | 均接受；小数属于秒；任意有限非空数字串，不截断超过六位的有效位 |
| 零偏移 +0000 与 +00 | 纳入读取支持并与 Z/+00:00 的同刻归一 |
| 完整 ISO 周日期、序数日期 | 在明确有效年/周/日校验后转为同一日序号 |
| 24:00:00（含基本式等支持组合） | 仅允许分、秒及小数全零；作为项目日界约定与次日 00:00:00 同刻排序 |
| 闰秒表示 | 本 profile 暂不支持；不能称为非法 ISO，显式报告“不支持的时间戳表示”；如要求支持须另选有离线规则/权威闰秒表的方案 |
| 非零偏移、扩展年份、日期/时间约简形式、小时或分钟小数、其他未枚举表示 | 不默认为非法 ISO，也不假定已经兼容；显式报告当前 profile 未支持 |
| 空串、格式不完整、非法日历日期、数字字段非法 | 显式报告无法解析；不默默当成最旧时间 |

### 3.1 精确语法与数值边界（待批准）

以下为推荐可直接审阅的工程读取语法，不把示例列表留给开发 Agent 自行扩展：

```text
CAL_EXT    = YYYY-MM-DD
CAL_BASIC  = YYYYMMDD
WEEK_EXT   = YYYY-Www-D
WEEK_BASIC = YYYYWwwD
ORD_EXT    = YYYY-DDD
ORD_BASIC  = YYYYDDD
TIME_EXT   = HH:MM:SS
TIME_BASIC = HHMMSS
FRACTION   = ('.' | ',') ASCII_DIGIT+   # 可选，仅为秒的小数
UTC_SUFFIX = 'Z' | '+00:00' | '+0000' | '+00'

EXT_STAMP   = (CAL_EXT | WEEK_EXT | ORD_EXT) 'T' TIME_EXT FRACTION? UTC_SUFFIX
BASIC_STAMP = (CAL_BASIC | WEEK_BASIC | ORD_BASIC) 'T' TIME_BASIC FRACTION? UTC_SUFFIX
STAMP       = EXT_STAMP | BASIC_STAMP
```

- DATE/TIME 必须同为基本式或同为扩展式；UTC_SUFFIX 与此独立，四种列举后缀可与任一允许的完整日期时间组合，例如 20261024T120000+00:00 可读。
- 仅 ASCII 数字，严格按完整文本匹配；不 strip 接受额外空白，不把大小写自动折叠；T、W、Z 为大写。
- 日历年/周所属年为 0001–9999；公历日期必须有效。周号 01–53 和周日 1–7 必须对该年有效；序数日 001–365/366 必须在该年。转换后的公历日期也须在此范围。
- 常规小时 00–23、分钟 00–59、秒 00–59；小数 1 位及以上有限数字，保留全部有效位，禁止仅用 float 或 datetime 微秒作为比较键。
- 小时 24 是单独的日界分支：分钟、秒与小数（若有）必须全零，只在排序键中归一到下一日。9999-12-31 的 24:00 越界，显式 StorageTimestampError，不回绕或改写原文。
- 秒 60 按“可能的闰秒表示，当前 profile 未支持”显式失败，不承诺判断其是否发生在真实闰秒日；其他可识别形状中的非法数字范围作为无效字段显式失败。
- 对未识别/profile 外文本只报告“不支持或无法识别”，不承诺先判定其是否属于完整 ISO 的合法表示。
- 混合基本/扩展日期时间、无秒、时间或日期约简、非零/未知偏移、扩展年份及其他未列举表示均为 profile 外，不能据此概括它们都违反 ISO。
- 读取 profile 是有意限定的工程承诺；它不是 ISO-8601 全集，因此需负责人批准后取代含糊承诺。

### 3.2 固定验收样例（待批准后实现）

| 输入/场景 | 获批后的预期 |
|---|---|
| 2026-10-24T12:00:00Z 与 .000000Z | 同刻，按 rowid DESC；原文不变 |
| .123456Z 与 .1234560000000000001Z | 后者较新，LIMIT 1 取后者 |
| 20261024T120000,123200+0000 | 可读，晚于扩展式 .123100Z |
| 2026-W43-6T12:00:00.123200Z 与 2026-297T12:00:00.123200Z | 均等于 2026-10-24 的相同时刻 |
| 2026W436T120000Z 与 2026297T120000+00 | 均等于对应完整扩展式时刻 |
| 2026-10-24T24:00:00.000Z 与 2026-10-25T00:00:00Z | 同刻，按 rowid DESC；两种插入顺序均测 |
| 2026-10-24T24:00:00.001Z；2026-02-30T12:00:00Z | 无效，显式 StorageTimestampError |
| 2016-12-31T23:59:60Z | 合法闰秒表示但当前 profile 不支持，显式 StorageTimestampError |
| 2026-10-24T12:00:00+08:00；2026-10-24T120000Z | profile 外，显式 StorageTimestampError |
| 2020-W53-7T00:00:00Z | 等于 2021-01-03T00:00:00Z |
| 2021-W53-1T00:00:00Z；2021-366T00:00:00Z | 当年不存在的周/序数日，显式失败 |
| 9999-W52-7T00:00:00Z；9999-12-31T24:00:00Z | 归一化公历日期越界，显式失败 |
| 2026-10-24T24:00:00.0000000000000000001Z | 小数非零，不能截断后按日界接受 |
| 任意不可比较记录位于候选集合末尾，limit=1 | 整次 list_recent 失败，不静默取一个可比较项 |

所有时间戳先后测试使用双插入顺序；同刻测试验证稳定次序，且 get/list_messages 保留原文访问作为恢复通路。

## 4. 无法解析或不支持记录的处置（待批准）

建议新增 StorageTimestampError(StorageError)，由 emowall.storage 包级导出；list_recent() 在不能为候选记录构造正确比较键时抛出该异常。

- 不将合法但未支持记录归为参数误用、磁盘故障或数据库外键违规。
- 区分“格式/日期无效”与“当前 profile 未支持”的安全诊断；不得在日志中记录整条会话或消息。
- 保留真实解析异常链；没有底层 SQLite 异常时不伪造 cause。
- 先验证整个候选集合并排序，再应用 limit；不得先截取再发现排序问题，也不得跳过无法比较的行。
- 任一无法比较记录会使整次 list_recent 失败，包括该记录可能不在最终前 N 条的情况。这会阻止正常会话列表加载，直到通过明确的数据修复或更广兼容支持处理；这是本方案需负责人接受的产品代价。
- 本轮不新增数据修复工具或 GUI，不为避免报错而改写历史库。

建议选择这一专用 StorageError 子类，以使未来 Stage 5 可继续统一捕获 StorageError，并针对该类提示兼容性问题。沿用 StorageIntegrityError 也会扩展其冻结语义，不能作为无需审批的捷径。

## 5. 私有实现建议与数据迁移

获批后优先采用私有精确键：日序号、秒字段、保留原有效位的十进制小数字符串；去掉小数尾零后同刻再按 rowid DESC。不使用浮点时间、SQLite %f 毫秒化或 datetime 六位截断作为排序判据。

查询取得一致的候选快照，构造键与验证完成后排序、应用 limit，最后仍返回原始时间字符串。必须对日界、闰日、同刻多种表示和双插入顺序验证。排序耗时与内存需要重新量化，不沿用现有 CTE 的性能结论。

无需数据迁移：Schema 保持 1，不增加归一化列/索引，不回写历史时间，不改 UUID、数据模型或方法签名。
